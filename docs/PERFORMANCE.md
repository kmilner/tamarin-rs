Across the 24 theory and worker-count combinations, Rust was 6.1–141× faster
than the Haskell release (median 35×). At one worker, Rust used 58–96% less
peak memory (median reduction 93%). From 1 to 16 workers, the Rust wall time
fell by 2.9–7.1× on the five theories that take more than three seconds
serially, apart from `Joux` (1.6×). Both provers agreed on every lemma verdict.
All 18 supported replays passed. The other six reached the Haskell 1.12
replay limitation described below.

The `not supported` entries in the RS+HS column are not failures of the
port: the emitted `Joux` and `wireguard` proofs are correct, but the
unpatched 1.12.0 release cannot replay them (`analysis incomplete`) due
to two upstream tamarin-prover issues —
[#871](https://github.com/tamarin-prover/tamarin-prover/issues/871)
(proof shape depends on thread count; already fixed on the develop
branch) and
[#881](https://github.com/tamarin-prover/tamarin-prover/issues/881)
(emitted proofs normalise differently on reload; fix pending in
[#882](https://github.com/tamarin-prover/tamarin-prover/pull/882)). The
patched `./setup.sh testing` build includes both fixes and re-verifies
both theories.

## Parallel proof search

Independent lemmas, DFS branches, and source saturation can run in parallel.
When multiple workers prove several selected lemmas, they build the shared
sources before starting proofs. Single-worker runs, single-lemma selections,
and interactive requests build sources on demand.
`--processors=N` sets the size of the worker pool shared by proofs and source
builds. The Maude process pool defaults to the same size and can be set with
`--maude-processes=M`. Oracle calls can overlap in both all-traces and
exists-trace proofs. A free worker can call the oracle on later cases while
an earlier case is still open. DFS retains the first witness in case order.
`--processors=1` serializes oracle calls within one batch run. Separate processes and concurrent interactive
requests can still call the same oracle at the same time.

The proofs and verdicts written to standard output do not depend on the worker
count, and a run fails with any worker count exactly when it fails with one.
Diagnostics on standard error can differ:

- A parallel run can build sources that a serial run never needs, so
  `[Saturating Sources]` progress lines can appear only with several workers.
- When more than one lemma or source lemma is in error, the error reported is
  the first one found, which need not be the first in the theory.
- An oracle can be called for cases that a serial run never reaches. Anything
  it writes to standard error, and any other side effect, then shows up only
  with several workers. Its answers for those cases are discarded.

Two cases fall outside that guarantee. An internal error (a panic) in a case
that a serial run never reaches still aborts the run. With
`TAM_PROVE_DEADLINE_MS` set, a case that several workers started before the
deadline can finish after it, so the result can go further than with one
worker.

Searching later cases early also costs memory: an exists-trace proof can hold
several open branches until an earlier one yields the trace, so a run close to
`--memory-limit` with one worker can exceed it with more.

A branch uses a Maude process of its own when the pool has one free, and
otherwise shares its parent's. Branches that share a process take turns on it.
If a branch that a single-worker search would reach sooner has to wait for a
later branch's Maude call, it stops that call once the call has run for a
quarter of a second, or for four times as long as Maude takes to start if that
is longer. The later branch repeats the call on a new Maude process, after
waiting longer each time this happens. With `--maude-processes=1`, branches
are searched in parallel and only their Maude calls queue.

## Memory limits

On Linux and macOS, `--memory-limit=<size>` monitors the combined memory of a
batch run, including Maude and other helpers. It measures RSS on Linux and
physical footprint on macOS. The macOS metric includes compressed memory and
excludes pages marked reusable, even when those pages remain resident:

```bash
tamarin-rs --memory-limit=4GiB --prove theory.spthy
```

`+RTS -M4G -RTS` is equivalent. Sizes accept bytes or binary K/M/G/T suffixes
(case-insensitive), also spelled KiB/MiB/GiB/TiB. Decimal quantities such as
`1.5G` work; `0` disables the limit. The last native or RTS memory setting wins.
Unlike GHC's `-M`, this measures the prover and helpers, not just the language heap.

Exceeding the threshold stops the job and exits **251**, matching GHC heap
exhaustion. Unfinished proofs are lost. This is an approximate limit: usage
can overshoot, shared pages can be counted more than once, and detached helpers
or unavailable process data may be missed. Linux RSS excludes swapped-out memory.
On macOS, a footprint query failure stops the job with an error unless the
sampled process has already exited.
Reducing `--maude-processes` also reduces baseline memory use.
